Method: timed interactive sessions

A simulated user sends a new request every few minutes

0:00 bug 1

3:00 bug 2

4:30 question

6:00 bug 3

9:00 urgent bug

Each bug names the files its fix touches and a hidden test that should start passing. “Keep working on the earlier ones.”

Measured per requestFrom the session’s own records
Received, answeredSeconds until the orchestrator read it, and until it replied
Touched, editedSeconds until any agent opened or changed the bug’s files
Fixed, correct, on timeGraded bugs, judged answers, ETA against the actual finish
So we built timed sessions on SWE-sweep. A simulated user sends a bug every few minutes, each one pointing at the files and a hidden test, and says keep working on the earlier ones. Later we added questions about the code, status checks and urgent bugs. For every request we measure how long until the orchestrator received it and answered it, how long until anyone touched or edited the relevant files, and in the end whether the bug was fixed, the answer correct, and the estimate accurate.
