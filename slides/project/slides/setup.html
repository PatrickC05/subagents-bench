Setup

A large orchestrator with small subagents, on real repositories

Models

Orchestrator: DeepSeek-V4.1-Flash

Subagents: Gemma-4-31B, up to 3 at once

Both served by Sail; we log raw tokens and timings

Harness

Our own agent loop inside harbor + Docker

Tools: bash, edit, read, list, search, and spawn_subagents

Benchmark

SWE-sweep: whole repositories with 6–14 hidden bugs

Each bug graded separately, so each can be its own request

Conditions: single agent · all-tools orchestrator that may delegate · manager that can only read, so every edit and test goes to a subagent · blocking or background spawns

Our setup: DeepSeek V4.1 Flash is the orchestrator, Gemma 4 31B is the subagent, up to three at a time, both on Sail. We wrote our own agent loop running inside harbor and Docker. The benchmark is SWE-sweep, where each task is a whole repository with several hidden bugs that are graded one by one. That matters because each bug can become its own user request. We compare a single agent, an orchestrator with all tools that may delegate, and a manager that can only read, so it must delegate, with spawns that either block or run in the background.
