The claim we test

Handing work to background subagents keeps the orchestrator free to answer the user

If it holds

  • New requests are read and answered sooner
  • Earlier work keeps going
  • Bugs still get fixed, at a cost we can name

Closest work: AsyncTool

Delayed tool feedback hurts agents; models that coordinate task switching do better.

We differ: we measure availability to the user and to requests not yet known, and whether the agent can say when each fix will be ready.

The claim is simple. If the orchestrator hands work to subagents that run in the background, it should stay free to read and answer the user. If that holds, new requests get answered sooner, the earlier work keeps going, and we still fix bugs. The closest work we found is AsyncTool, which shows delayed tool feedback hurts agents. We differ in focus: we care about availability to the user and to requests that are not known yet, and whether the agent can predict when its work will be done.
