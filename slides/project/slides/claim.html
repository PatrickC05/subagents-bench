The claim we test

Handing work to background subagents keeps the orchestrator free to answer the user

If it holds

  • New requests are read and answered sooner
  • Earlier work keeps going
  • Bugs still get fixed, at a cost we can name

Closest work

Gaia2 (Froger et al., ICLR 2026): environments that change on their own, with time limits; GPT-5 (high) leads at 42% but fails time-sensitive tasks.

AsyncTool: delayed tool feedback hurts agents; those that coordinate task switching do better.

We differ: a coding agent’s availability to the user while its own work runs, whether delegating to small subagents buys it, and whether it can say when each fix will be ready.

Gaia2: arxiv.org/abs/2602.11964

The claim is simple. If the orchestrator hands work to subagents that run in the background, it should stay free to read and answer the user. If that holds, new requests get answered sooner, the earlier work keeps going, and we still fix bugs. The closest work is Gaia2, from Meta at ICLR 2026, which benchmarks agents in environments that change on their own under time limits; even the best model, GPT-5 on high, fails the time-sensitive tasks. AsyncTool shows delayed tool feedback hurts agents. We differ in focus: we care about availability to the user and to requests that are not known yet, and whether the agent can predict when its work will be done.
