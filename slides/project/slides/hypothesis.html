Hypothesis

Handing work to background subagents keeps the orchestrator free, and that improves interactivity

If it holds

  • New requests get a reply sooner
  • Earlier work keeps going
  • Estimates and priorities are handled while work runs

What could break it

  • The orchestrator’s own thinking is the bottleneck
  • Coordinating subagents adds overhead
  • Delegated work is done worse
So our hypothesis: if the orchestrator hands work to subagents that run in the background, it stays free to talk to the user, and interactivity improves. If that holds, requests get replies sooner, earlier work keeps going, and the agent can give estimates and reprioritize while work runs. It could fail if the orchestrator's own thinking is the bottleneck, if coordinating subagents costs more than it saves, or if delegated work is done worse.
